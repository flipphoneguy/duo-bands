# M5: EU firmware vs US firmware

A full comparison of two complete modem firmware sets for the M5. Terms are explained in `01-basics.md`, and the method is the same as in `02-qin-f21.md`.

Everything under "Findings" was checked directly in the files. Things that are only likely, or weren't examined, are at the end under "Not proven / not examined".

## What was compared

| | EU set | US set |
|---|---|---|
| Source | `~/github/public/f21_bands_swap/bands/m5/stock.tar.xz` | `~/github/public/f21_bands_swap/bands/m5/us.tar.xz` |
| Contents | `md1img_a.bin`, `nvdata.bin`, `nvram.bin`, `nvcfg.bin` | same |

Both sets work on the same M5 phones (from you). All four partitions differ between the two sets, and none of them matches either F21 set.

How each part was read is the same as for the F21: md1img split into parts; tables found in `md1rom` and decoded with each build's own dictionary; nvdata and nvcfg extracted with `debugfs` (after replaying the EU nvcfg journal on a copy); every NVRAM record matched by LID and decoded field by field; encrypted records decrypted with the known MediaTek key.

## Short answer: what makes a set EU or US

On the M5, the EU and US sets differ in band setup in these places:

1. **The band list (25 slots)**: in `md1rom` (two copies, plus slot flags) and in nvdata (`CALIBRAT/EL03_001`).
2. **The LTE wiring per slot (route tables)**: only in `md1rom`.
3. **LTE calibration per slot**: nvdata `CALIBRAT/EA10_001`, `EA40_001`, `EA50_001`, plus self-calibration `EL90`–`EL93`.
4. **LTE power rules**: MPR and A-MPR in nvdata (`EL01`, `EL02`, `EL0K`, `EL5C`).
5. **LTE carrier-aggregation linkage**: nvdata `CALIBRAT/EL04_001`. This one didn't differ on the F21.
6. **LTE front-end bypass commands**: nvdata `EL75`–`EL79`.
7. **3G band setup**: nvdata `UL03_000` and the 3G front-end records.
8. **2G band on/off, one receive input and two MIPI values**: nvdata `LA3S`, `LA9W`, `LA3M`, `LA3O`.
9. **TD-SCDMA**: only the EU build supports it.

These are **not** where the difference lies:
- the generic band table (identical)
- the carrier layer (the SBP record and the SBP feature names are identical)
- nvcfg

Compared with the F21, the two M5 builds are much closer to each other: same version, same signing keys, same record layouts.

### Signing keys

Both images carry the same RSA keys: `9af8a28bf1` and `952a0d4b2c` in `cert1`, and `952a0d4b2c` in `cert2` (fingerprints as in the F21 doc). These are also the keys of the **F21 EU** image.

Found by the Band 3 entry at EU `0x10f51bc` and US `0xe76e30`. The 59-entry table is **identical** in both, and identical to the F21's.

### Same paths, different bands

Every field of each US entry compared with the EU entries (except band and MIPI table number):

| US band | Shares the path of EU | Result |
|---|---|---|
| B4 | B1 | **identical** |
| B66 | B1 | **identical** |
| B5 | B5 | **identical** |
| B7 | B7 | **identical** |
| B12 | B20 | **identical** |
| B17 | B20 | **identical** |
| B71 | B28 | **identical** |
| B13 | B20 | identical except main input (PRX10, which is EU B8's main input) |
| B2 | none | TX like EU B1/B3 (MB1). Main input PRX7 and diversity DRX4 are unused in EU. RX pins 40 like EU B3 |
| B29 | none | main input PRX9 (EU B39's), diversity DRX9 and pins 32 (EU B8's), no TX |

Since the same phones work with both sets, these shared paths pass both bands. No US band uses the full path of EU B3, B8, B38, B39, B40 or B41. Parts of B8's path (main input PRX10, diversity DRX9, pins 32) are reused by US B13 and B29.

### M5 wiring compared with the F21

Same band, same set type, every field compared:

| | Identical on both phones | Different |
|---|---|---|
| EU | B1, B5, B7, B8, B38, B39, B40, B41 | B3 (diversity input), B20 (main input), B28 (main input and control pins) |
| US | B2 | B4, B13, B66 (main input); B12, B17 (diversity input and pins); B71 (both inputs and pins) |

The two phones' radio configurations are closely related but not the same.

### Dictionaries and strings

- EU knows 483 NVRAM record types, US 456. The 27 extra in EU are all TD-SCDMA (`NVRAM_EF_AST_*`), and US has none of its own.
- No record layout changed size between the two (same version). There are 75 structure definitions only in EU and 10 only in US.
- Strings in `md1rom`: 15,623 shared, 1,291 only in EU, 582 only in US.
- These band-related SBP feature names are present in **both**: `SBP_DISABLE_LTE_BAND_BY_PLMN`, `SBP_LTE_CUSTOM_DISABLE_BAND_BY_PLMN`, `SBP_CUSTOM_BAND_DISABLE_FOR_PLMN`, `SBP_DISABLE_BANDS_IF_SIM_IS_VISIBLE_SIM`, `SBP_DISABLE_GSM_FOR_US_MCC`, `SBP_DISABLE_LTE_B41`.

### LTE band setup records

**Band indicator** (`CALIBRAT/EL03_001`): the same lists as md1rom.
- EU: B1, B3, –, B5, B7, B8, B20, B28, B38, B39, B40, B41
- US: B2, B4, B5, B7, B12, B13, B17, B29, B66, B71

**Calibration per slot** (`EA10` receive gain, `EA40` TX DAC, `EA50` amplifier levels): one record per slot. Records 14 and up are empty in both.

| | Empty records among slots 0–13 |
|---|---|
| EU | 2, 12, 13 (all three tables) |
| US receive gain | 10–13 |
| US TX tables | 7 (B29) and 10–13 |

So US B29 has receive calibration but no transmit calibration, which fits a download-only band.

**Self-calibration:**

| Record | File | Records that differ |
|---|---|---|
| `RF_SELF_CAL_RX_DC_IRR` | `EL90` | 11 of 26 |
| `RF_SELF_CAL_RX_IIP2` | `EL91` | 3 of 26 |
| `RF_SELF_CAL_DET_TX` | `EL92` | 11 of 26 |
| `RF_SELF_CAL_TX_SB` | `EL93` | 2 of 5 |

`EL1_FREQADJTBL` (`EA03`) has identical data.

**MPR** (`EL01`): rows follow the band list. EU rows B1, B3, B5, B7, B8, B20, B28, B38, B39, B40, B41. US rows B2, B4, B5, B7, B12, B13, B17, B29, B66, B71. All rows within a set have the same values. The CA versions `EL0K` and `EL5C` also differ.

**A-MPR** (`EL02`):

| Row | EU band (rule index) | US band (rule index) |
|---|---|---|
| 0 | B1 (5) | B2 (3) |
| 1 | B20 (10) | B4 (3) |
| 2 | B28 (18) | B13 (7) |
| 3 | B41 (4) | B66 (3) |

These are the same bands and rule indexes as the F21's EU and US sets.

**CA linkage** (`EL04`, `FE_CA_LINKAGE_DATABASE`): differs (21 fields). It links receive and transmit routes for carrier aggregation. Its contents didn't decode cleanly (the layout appears misaligned in my decoder), so only the fact that it differs is certain.

**MIPI bypass TX** (`EL75`–`EL79`): all five differ, contents not decoded.

All 34 LTE record types that are saved in nvdata are the same 34 in both sets. Of 103 LTE record types, the other 69, including both route tables, exist only as md1rom defaults in both sets.

### 3G band setup

`NVD_DATA/UL03_000`:

| | 3G bands (position) | Main RX | TX |
|---|---|---|---|
| EU | B1 (HB1), B2 (HB2), B5 (HB3), B8 (LB1) | B1 PRX2, B2 PRX7, B5 PRX5, B8 PRX10 | B1/B2 MB1, B5/B8 LB2 |
| US | B2 (HB1), B4 (HB2), B5 (HB3) | B2 PRX7, B4 PRX2, B5 PRX5 | all MB1 except B5 LB2 |

No diversity input is used for 3G in either set.

| Records | EU | US | Same? |
|---|---|---|---|
| LOWBAND1 (TPC, RX event, RX data, TX event, TX data) | filled | empty | no |
| HIGHBAND1 TPC, RX data, TX data | filled | filled | no |

3G calibration: the files for B1, B2, B4, B5 and B8 differ in content (pathloss `UL11`/`12`/`14`/`15`/`18`, second-antenna pathloss `HL10`/`13`/`17`, TX DAC, amplifier levels, power-on). Those are exactly the 3G bands used by either set combined. The 3G calibration files for other bands are identical. `ULBC`/`ULBD` (frequency correction) differ.

### 2G band setup

| Record | EU | US |
|---|---|---|
| `L1_CUSTOM_BAND_SUPPORT` (`LA3S`) | GSM850, GSM900, DCS1800, PCS1900 all on | GSM850 on, GSM900 **off**, DCS1800 **off**, PCS1900 on |
| `L1_2G_RF_PARAMETER` (`LA9W`), DCS1800 main input | PRX1 | PRX9 |
| `L1_MIPI_CTRL_TABLE_GSM900` (`LA3M`), one RX MIPI value | 136 | 156 |
| `L1_MIPI_CTRL_TABLE_DCS1800` (`LA3O`), one RX MIPI value | 152 | 148 |
| `L1_MIPI_CTRL_TABLE_DCS1800` (`LA3O`), one TX MIPI value | 247 | 63 |

The other 2G inputs are the same in both: GSM850 PRX5, GSM900 PRX10, PCS1900 PRX7, all diversity DRX1.

This is the opposite of the F21 US set, which turned off GSM850/PCS1900 and kept GSM900/DCS1800. In both phones' US sets, DCS1800 moves from PRX1 to PRX9.

2G calibration that differs:
- ramp tables for all four bands (`LA06`–`LA09`), EPSK ramps for GSM850 and PCS1900 (`LA0A`, `LA0D`), interslot `LA0E`
- AGC pathloss `LA05`, AFC `LA0I`, special coefficients `LA0K`, crystal `LA0Q`, LNA pathloss `LA0V`, crystal load offset `LA1V`, `L1_RFC` (`LA26`)
- `L1_EPSK_TXPC` (`LA0U`): EU `is_calibrated = 0`, US `is_calibrated = 1`

`L1_TAS_CUSTOM_INHERIT_LTE_BAND` (`LA9Z`) differs in five values whose meaning is unknown.

### Carrier layer (SBP)

`SBP_MODEM_CONFIG` (`SP80_726`) is **byte-identical** in both. Decrypted, `sbp_mode` = `0xFFFFFFFF` ("not set").

- `MML1_CAL_DATA_DL_CHECK` (`ML0D`)
- `MML1_TEMPERATURE_DAC` (`ML5A`)
- `MML1_GPS_CO_TMS_DATA` (`ML4A`)

## Findings: nvram partition

- EU contains 149 LDI files, all byte-identical to EU nvdata. Two of them (`TD2B`, `TD6Z`) are TD-SCDMA calibration that US doesn't have.
- US contains 147 LDI files. 146 match US nvdata. The exception is the IMEI file, where nvram holds an older IMEI than nvdata.
- EU vs US: none of the 147 shared files is identical.

## Findings: nvcfg partition

| File | Result |
|---|---|
| `agps_nvram.txt` | **identical** (unlike the F21) |
| `fg/car_tune_value` | identical |
| `fg/old_fg_data` | differs (battery fuel-gauge data) |

There's no factory test database in either set. Nothing in nvcfg relates to bands.
