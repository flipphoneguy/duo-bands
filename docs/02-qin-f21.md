# Qin F21: EU firmware vs US firmware

A full comparison of two complete modem firmware sets for the Qin F21. Terms are explained in `01-basics.md`.

Everything under "Findings" was checked directly in the files. Things that are only likely, or weren't examined, are listed separately at the end under "Not proven / not examined".

## What was compared

| | EU set | US set |
|---|---|---|
| Source | `~/github/public/f21_bands_swap/bands/stock.tar.xz` | `~/github/public/f21_bands_swap/bands/us.tar.xz` |
| Contents | `md1img_a.bin`, `nvdata.bin`, `nvram.bin`, `nvcfg.bin` | same |

Both sets work on the same F21 phones. That comes from you: hundreds of users run either one on the same hardware. Every one of the four partitions differs between the two sets.

How each part was read:
- **md1img**: split into its parts using the part headers. The tables were then located in `md1rom` and decoded with each set's own dictionary (`md1_mddbmetaodb`).
- **nvdata / nvcfg**: the ext4 journal was replayed on copies of the images (the EU images had unreplayed journal entries), then all files were extracted with `debugfs`. Every NVRAM file was matched to its record type through the LID in its header and decoded field by field with the dictionary.
- **nvram**: the LDI files inside were found and compared with the nvdata copies.
- Encrypted records (IMEI, barcode, SBP) were decrypted with the known MediaTek AES key.

## Short answer: what makes a set EU or US

On the F21, these are the places where EU and US differ in band setup:

1. **The band list (25 slots)**: in `md1rom` (built-in default) and in nvdata (`CALIBRAT/EL03_001`).
2. **The LTE wiring per slot (route tables)**: only in `md1rom`. nvdata has no copy.
3. **LTE calibration per slot**: in nvdata (`CALIBRAT/EA10_001`, `EA40_001`, `EA50_001`), plus self-calibration (`EL90`–`EL93`).
4. **LTE power rules**: MPR and A-MPR in nvdata (`NVD_DATA/EL01_001`, `EL02_001`, `EL0K_000`, `EL5C_000`).
5. **LTE front-end bypass commands**: nvdata `CALIBRAT/EL75_000`–`EL79_000`.
6. **3G band setup**: nvdata `NVD_DATA/UL03_000` and the 3G front-end records.
7. **2G band on/off and one receive input**: nvdata `NVD_DATA/LA3S_000` and `LA9W_000`.

These are **not** where the difference lies:
- the generic band table (identical in both)
- the carrier layer (SBP)
- the nvcfg partition

The same physical receive and transmit paths are used for EU bands in one set and US bands in the other (details below).

They're two different builds of the same base project, so a raw byte comparison of `md1rom` shows differences almost everywhere. The comparisons below are table by table.

The two sets also came from two different phones: their factory barcodes differ, and the calibration values differ for every calibrated band. The IMEIs in both sets were changed by you.

## Findings: md1img

### Parts

Both images contain the same 21 parts. The only difference is the order of the six `md1_filter*` parts, and EU's first certificate being named `cert1md` where US has `cert1`.

| Part | Same in both? | What differs |
|---|---|---|
| `md1rom` | no | different version (details below) |
| `md1dsp` | no | different version (same size, 4,358,428 bytes) |
| `md1drdi` | **yes** | all zeros in both (empty) |
| `cert1*`, `cert2` | no | **signed with different keys** (below) |
| `md1_filter*` (6) | no | EU 9,539 bytes, US 9,519 bytes; logging config |
| `md1_emfilter` | no | logging config, same size |
| `md1_mddb`, `md1_mddbmeta`, `md1_mddbmetaodb`, `md1_mdmlayout` | no | debug databases for each version |
| `md1_file_map` | no | different line order and version names |

### Signing keys

Each certificate holds RSA-2048 keys. Fingerprints (first 10 hex digits of the SHA-256 of the key):

| | Keys in `cert1` | Key in `cert2` |
|---|---|---|
| EU | `9af8a28bf1`, `952a0d4b2c` | `952a0d4b2c` |
| US | `c13dab1362`, `f6e995d36b` | `f6e995d36b` |

The two images are signed with completely different keys, and the same F21 phones run both.

### Generic LTE band table

Found by the Band 3 entry (`03 00 82 46 70 49 cc 42 ba 45`) at EU `0xe89b18` and US `0xe41db8`. The full 59-entry table (24 bytes each) is **byte-for-byte identical** in both. Each entry holds: band number, downlink low/high, uplink low/high (100 kHz units), downlink and uplink EARFCN offsets, and the real band number again at the end. It covers B1–B14, B17–B48, B65–B71 and B252–B255. B15, B16 and B65 are present but empty.

### Band list in md1rom (built-in default)

Two copies in each `md1rom`, each preceded by a row of one-byte flags (one per slot):

| | Offsets | Slot flags | Slots |
|---|---|---|---|
| EU | `0xf906c8`, `0xfe7228` | `01` × 14 | B1, –, B3, B5, B7, B8, –, B20, B28, B34, B38, B39, B40, B41 |
| US | `0xf3d0a0`, `0xf87228` | `01` × 7 | B2, B4, B12, B13, B17, B66, B71 |

"–" is an empty slot (0). In US, B66 and B71 are stored as 50 and 55 (MediaTek's numbering). The EU flags are 1 for the two empty slots too.

### Same paths, different bands

Comparing every field of each US route entry with an EU entry (all fields except the band number and the MIPI table number):

| US band | Compared with EU | Result |
|---|---|---|
| B71 | B5 | TX and RX **identical** |
| B13 | B20 | TX and RX **identical** |
| B12 | B28 | Identical except one control bit (value 2): EU sets it on both TX (`pt1`/`pt2` = 2) and RX (50 vs 48) |
| B17 | B28 | Same as B12 |
| B2 | B3 | TX identical. RX identical except main input: B2 uses PRX7, B3 uses PRX1 |
| B4, B66 | B1 | TX identical. RX identical except main input: B4/B66 use PRX1, B1 uses PRX2 |
| B4, B66 | B3 | TX identical. RX shares the main input (PRX1) but uses B1's diversity input (DRX1) and control pins (`0x38`) |

Notes on inputs:
- EU doesn't use PRX7 for LTE. US uses it for B2.
- PRX1 is EU B3's main input and US B4/B66's main input.
- US doesn't have B5 (a US band). Its old path (PRX5/DRX8/LB2, pins `0x10`) is used by B71.

Since the same phones work with both sets, these shared paths pass both the EU band and the US band that use them.

### Dictionaries (record types each version knows)

- EU knows 455 NVRAM record types, US 453. Only in EU: `NVRAM_EF_ERRC_CUSTOM_FEATURE_LID` and `NVRAM_EF_GSM_CUSTOM_DISABLE_BAND_LIST_LID`.
- 19 record layouts changed size between versions (for example the SBP, LTE preference and IMS profile records). 18 layouts exist only in EU, 12 only in US.

### Text strings in md1rom

14,929 strings are shared, 1,301 exist only in EU and 812 only in US.

Band-related carrier (SBP) feature names present in **EU only**:
- `SBP_CUSTOM_BAND_DISABLE_FOR_PLMN`
- `SBP_DISABLE_BANDS_IF_SIM_IS_VISIBLE_SIM`
- `SBP_DISABLE_GSM_FOR_US_MCC`

Present in **both**:
- `SBP_DISABLE_LTE_BAND_BY_PLMN`
- `SBP_LTE_CUSTOM_DISABLE_BAND_BY_PLMN`
- `SBP_DISABLE_LTE_B41`

### LTE band setup records

**Band indicator** (`CALIBRAT/EL03_001`, LID 60436): the same lists as the md1rom copies.
- EU: B1, –, B3, B5, B7, B8, –, B20, B28, B34, B38, B39, B40, B41
- US: B2, B4, B12, B13, B17, B66, B71

**Calibration per slot.** These three each hold one record per slot, in the same order as the band list:

| Record | File | Records |
|---|---|---|
| `EL1_RSSIGAINTBL_TYPE1` (receive gain) | `CALIBRAT/EA10_001` | 34 |
| `EL1_TXDAC` (transmit power) | `CALIBRAT/EA40_001` | 39 |
| `EL1_TXPAOCTLEV` (amplifier levels) | `CALIBRAT/EA50_001` | 39 |

Records 0–13 differ between the sets, and records 14 and up are empty in both. EU records 1 and 6 are empty (the empty slots), and US records 7–13 are empty. Each filled record starts with its band number, which matches the slot.

**Self-calibration** (differences per record):

| Record | File | Records that differ |
|---|---|---|
| `EL1_RF_SELF_CAL_RX_DC_IRR` | `EL90_001` | 12 of 26 |
| `EL1_RF_SELF_CAL_RX_IIP2` | `EL91_001` | 3 of 26 |
| `EL1_RF_SELF_CAL_DET_TX` | `EL92_001` | 12 of 26 |
| `EL1_RF_SELF_CAL_TX_SB` | `EL93_001` | 2 of 5 |

`EL1_FREQADJTBL` (`EA03_001`) has identical data in both. Only its file header differs.

**MPR** (`NVD_DATA/EL01_001`): one row per band. EU rows are B1, B3, B5, B7, B8, B20, B28, B34, B38, B39, B40, B41. US rows are B2, B4, B12, B13, B17, B66, B71. Within each set every row has the same values (QPSK1 256, 16QAM0 256, 16QAM1 512, 64QAM0 512, 64QAM1 768), so the rows just follow the band list. The carrier-aggregation MPR records `EL0K_000` and `EL5C_000` also differ.

**A-MPR** (`NVD_DATA/EL02_001`):

| Row | EU band (rule index) | US band (rule index) |
|---|---|---|
| 0 | B1 (5) | B2 (3) |
| 1 | B20 (10) | B4 (3) |
| 2 | B28 (18) | B13 (7) |
| 3 | B41 (4) | B66 (3) |

Each row also has its own data values, which differ.

**MIPI bypass TX** (`CALIBRAT/EL75_000`–`EL79_000`, "0th" to "4th band"): front-end command lists. All five differ (66 fields each). Their exact contents weren't decoded reliably.

### 3G band setup

`NVD_DATA/UL03_000` (`UL1_3G_RF_PARAMETER`):

| | 3G bands | Wiring |
|---|---|---|
| EU | B1, B5, B8 | B1: PRX2/DRX9, TX MB1. B5: PRX5/DRX4, TX LB2. B8: PRX10/DRX4, TX LB2 |
| US | B1, B8 | B1: PRX2/DRX9, TX MB1. B8: PRX10/DRX4, TX LB2 |

US drops 3G B5. B8 has the same wiring in both but sits in a different position in the list: EU position "LB2", US position "HB2".

The 3G front-end records follow these position changes:
- **MIPI** (TPC, RX event, RX data, TX event, TX data): the LOWBAND1 and LOWBAND2 records are filled in EU and empty in US. The HIGHBAND2 records are empty in EU and filled in US. The HIGHBAND1 records are identical in both, and HIGHBAND3 and the ASM isolation records are empty in both.
- **`ULN1`** (MIPI startup commands): differs. **`ULN2`** (MIPI sleep commands): filled in EU, empty in US.
- **Amplifier power source**: `ULN6` (HB2: EU invalid, US PMIC), `ULN8` (LB1: EU PMIC, US invalid), `ULN9` (LB2: EU PMIC, US invalid).

3G calibration files for B1, B5 and B8 differ in content: `UL11`, `UL15`, `UL18` (pathloss), `HL14` (B5 second-antenna pathloss), `UL1B`, `UL1F`, `UL1I` (TX DAC), `UL1M`, `UL1Q`, `UL1T` (amplifier levels), `ULBQ`, `ULBU`, `ULBX` (power-on). Also `ULBC`/`ULBD` (frequency correction). The 3G calibration files for other band numbers are identical in both.

### 2G band setup

| Record | EU | US |
|---|---|---|
| `L1_CUSTOM_BAND_SUPPORT` (`NVD_DATA/LA3S_000`) | GSM850 on, GSM900 on, DCS1800 on, PCS1900 on | GSM850 **off**, GSM900 on, DCS1800 on, PCS1900 **off** |
| `L1_2G_RF_PARAMETER` (`NVD_DATA/LA9W_000`), DCS1800 receive input | PRX1 | PRX9 |
| `L1_MIPI_CTRL_TABLE_DCS1800` (`LA3O_000`), one MIPI value | 16 | 4 |
| `L1_MIPI_CTRL_TABLE_PCS1900` (`LA3Q_000`), one MIPI value | 5 | 4 |

In US, PRX1 is the main input for LTE B4/B66. In EU it's shared by LTE B3 and GSM DCS1800.

2G calibration that differs:
- ramp tables for GSM850, GSM900, DCS1800 (`LA06`–`LA08`) and their EPSK versions (`LA0A`–`LA0C`), plus `LA0E`
- `LA05` (AGC pathloss), `LA0I` (AFC), `LA0K` (RF special coefficients), `LA0Q` (crystal), `LA0V` (LNA pathloss)
- `LA26` (`L1_RFC`)

PCS1900 ramp tables are identical. `L1_TAS_CUSTOM_INHERIT_LTE_BAND` (`LA9Z_000`) differs in five values, whose meaning wasn't worked out.

### Carrier layer (SBP)

`SBP_MODEM_CONFIG` (`SP80`) is encrypted. Decrypted, its `sbp_mode` field is `0xFFFFFFFF` in both sets, the value used for "not set". The record layout is 124 bytes in EU and 116 in US (version difference), and one byte further in differs (`0x16` vs `0x17`, meaning unknown). The US-only `SBP_MODEM_DATA_CONFIG` (`SP81`) wasn't decrypted.

### Outside the modem NVRAM

These differ:

- `AllFile` and `AllMap` (not decoded)

### LTE records saved in nvdata vs built-in only

Of the 100 LTE radio (`EL1`) record types:
- **34 are saved in nvdata**: band indicator, calibration, MPR/A-MPR, MIPI bypass, CA linkage, HPUE and self-calibration.
- **66 exist only as md1rom defaults** in both sets. These include the route tables (`FE_TX_ROUTE_DATABASE`, `FE_RX_ROUTE_DATABASE`), the main MIPI tables (`MIPI_TX_DATA`, `MIPI_RX_DATA`, events), antenna and TAS tables, split-band and filter-mode tables, and the TX power offset/backoff tables.

So to move an F21 from EU to US bands, the md1rom wiring has to change along with the nvdata records.

## Findings: nvram partition

- Contains 147 LDI files in both sets: the calibration records plus the IMEI file.
- **US**: all 147 are byte-identical to the nvdata copies.
- **EU**: 146 are identical. The odd one out is the IMEI file, where nvram still holds an older IMEI than nvdata.
- EU vs US: 9 files identical, 138 different. These are the same differences seen in nvdata.

## Where each restriction sits

For an F21 on the EU set, US bands are missing in all of these places at once:

| Place | EU set | US set |
|---|---|---|
| md1rom band list (2 copies) | no US bands | US bands |
| md1rom route tables (TX, RX) | no entries for US bands | entries pointing at existing paths |
| nvdata band indicator (`EL03`) | no US bands | US bands |
| nvdata LTE calibration (`EA10`, `EA40`, `EA50`) | no records for US bands | records for US bands (from another unit) |
| nvdata MPR / A-MPR | EU band rows | US band rows |
| nvdata LTE MIPI bypass (`EL75`–`EL79`) | EU contents | US contents |
| nvdata 3G setup | B1, B5, B8 | B1, B8 |
| nvdata 2G band support | all four GSM bands | GSM850 and PCS1900 off |

Not a restriction: the generic band table (identical), SBP (not set in either), nvcfg.
